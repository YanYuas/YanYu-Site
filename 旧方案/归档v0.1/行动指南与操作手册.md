## 1. 一分钟认识这个知识库



* 这是一个用 **MkDocs + Material 主题**做的网站。你写的是普通的 **Markdown（.md）文件**，网站自动生成。

* 所有内容放在 `docs/` 文件夹里。**文件夹结构 = 网站导航结构**。

* 改完文件，网站自动刷新，不用复杂操作。

* 风格是**奶油糖果风**，但已经留好接口，以后能整体换成别的风格。

* 网站最终**私有部署**，只有你（和授权的人）能看。

### 文件夹总览



```
YanYu-MathModeling/

├── mkdocs.yml              # 网站配置（一般不用动）

├── requirements.txt        # 依赖清单（云端构建用）

├── 行动指南与操作手册.md     # 就是本文件

├── overrides/              # 站点级自定义模板（一般不用动）

└── docs/                   # ★ 所有内容都放这里

&#x20;   ├── index.md            # 首页

&#x20;   ├── tags.md             # 标签索引

&#x20;   ├── stylesheets/        # 奶油糖果样式

&#x20;   ├── javascripts/        # 公式脚本

&#x20;   ├── assets/images/      # 图片集中处

&#x20;   ├── 00\_我的数模研究/      # 11 个内容分区……

&#x20;   └── ...
```

## 2. 快速开始（3 步看到网站）

**第 1 步**：打开 PowerShell，进入项目目录。



```
Set-Location "D:\YanYuas\MathematicalModeling\YanYu-MathModeling"
```

**第 2 步**：启动本地预览服务器。



```
python -m mkdocs serve
```

**第 3 步**：浏览器打开它提示的地址（一般是 `http://127.0.0.1:8000`）。

之后只要你保存任何文件，网页会自动刷新。**看完按&#x20;**`Ctrl + C`**&#x20;停止服务器。**

> 如果提示找不到 mkdocs，说明环境没装好，看第 14 节。

## 4. 命名规范

好名字让导航一目了然，也避免乱档。

**文件夹和文件名：**



* 用编号控制顺序：`01_`、`02_`、`99_`

* 用中文说清楚内容，不用 "新建文档"" 最终版 2""副本" 这类名字

* 单词之间用下划线 `_`，**不要用空格**

* 示例：


  * `03_单纯形法原理.md`

  * `2026_国赛数学建模竞赛`

  * `线性规划_代码模板.py`

**版本迭代：**



* 正在写的文档直接改原文件，Git 会自动保存历史，**不要手动加 "v2"" 最终最终版 "**

* 比赛中的过程稿如果确实要留，放进该比赛的 `99_归档`，并写明日期，如 `论文_过程稿_20260912.md`

**文档内部标题：**



* 每个文档开头用一个一级标题 `# 标题`（和文件名表达一致）

* 标题层级不要跳级（`#` 之后用 `##`，不要直接用 `###`）

## 5. 怎么写一篇文档（Markdown 常用写法）

Markdown 就是加了简单符号的纯文本。下面这些覆盖 90% 的需求。



```
\# 一级标题（文档标题）

\## 二级标题

\### 三级标题

普通文字直接写。\*\*加粗\*\* ，\*斜体\* ，\~\~删除线\~\~ 。

\- 无序列表项

\- 另一项

&#x20; \- 缩进的子项

1\. 有序列表第一项

2\. 第二项

\[这是一个链接]\(https://example.com)

\> 这是引用块，用来放引用的话或重点提示。

\| 列1 | 列2 |

\|---|---|

\| 数据 | 数据 |

行内代码用反引号：\`x = 1\`
```

**想让图片或内容居中、加样式**，可以用属性语法：



```
!\[图片描述]\(images/a.png){ align=center }
```

## 6. 怎么写数学公式

网站用 MathJax 渲染公式，已经配置好。直接写：

**行内公式**（嵌在文字里）：用单个美元符号。



```
目标函数是 \$z = c^T x\$，约束为 \$Ax \le b\$。
```

**独立公式**（单独一行、居中）：用两个美元符号。



```
\$\$

\max\_{x}\ z = c^{T} x

\$\$
```

**带上标下标、求和：**



```
\$\$

z = \sum\_{i=1}^{n} c\_i x\_i, \qquad x\_i \ge 0

\$\$
```

**矩阵：**



```
\$\$

A = \begin{pmatrix}

1 & 2 & 3 \\\\

4 & 5 & 6

\end{pmatrix}

\$\$
```

**分段函数 / 方程组：**



```
\$\$

f(x) = \begin{cases}

x, & x \ge 0 \\\\

-x, & x < 0

\end{cases}

\$\$
```

常用符号：`\le \ge \ne \approx \sum \prod \int \frac{a}{b} \sqrt{x} \alpha \beta \lambda \mu \pi \to \Rightarrow \in \subset \forall \exists \infty`。

!!! note "小提示"

想在正文显示一个真正的美元符号（不是公式），写成 `\$` 即可。

## 7. 怎么写提示框、代码、流程图

### 提示框（admonition）

用 `!!! 类型 "标题"`，类型决定颜色（语义色只表达状态）：



```
!!! note "背景说明"

&#x20;   这里写背景、概念解释。（蓝色）

!!! tip "小技巧"

&#x20;   这里写好用的技巧、推荐做法。（绿色）

!!! warning "注意"

&#x20;   这里写容易出错、要小心的地方。（黄色）

!!! danger "严重问题"

&#x20;   这里写不能犯的错误。（红色）
```

想让提示框可以折叠，把 `!!!` 换成 `???`；想默认展开，用 `???+`。

### 代码块

用三个反引号，并写上语言名，代码会高亮、右上角有复制按钮：



```
\`\`\`python

import numpy as np

x = np.array(\[1, 2, 3])

print(x.mean())

\`\`\`
```

### 代码逐行注释（数字标记）

这是你特别需要的 "每一步都标注"。在代码里用 `# (1)` 标记，代码下方再解释：



```
\`\`\`python

c = \[-3, -5]          # (1)

A = \[\[1, 0], \[0, 2]]  # (2)

res = linprog(c, A\_ub=A)  # (3)

\`\`\`

1\.  \`c\`：目标函数系数，负号因为要求最大值而库默认求最小

2\.  \`A\`：不等式约束的系数矩阵

3\.  \`linprog\`：调用单纯形/内点法求解
```

### 流程图（Mermaid）

用 `mermaid` 代码块，网站自动画成图，不用手画：



```
\`\`\`mermaid

flowchart TD

&#x20;   A\[读题] --> B\[确定决策变量]

&#x20;   B --> C{是否线性?}

&#x20;   C -- 是 --> D\[建立线性规划]

&#x20;   C -- 否 --> E\[考虑非线性方法]

&#x20;   D --> F\[求解与检验]

&#x20;   E --> F

\`\`\`
```

### 内容选项卡（同一处切换多组内容）



```
\=== "Python"

&#x20;   \`\`\`python

&#x20;   print("hello")

&#x20;   \`\`\`

\=== "MATLAB"

&#x20;   \`\`\`matlab

&#x20;   disp('hello')

&#x20;   \`\`\`
```

## 8. 怎么放图片和文件

**图片：**



1. 把图片复制到 `docs/assets/images/`（或该分区的 images 目录）

2. 在文档里引用：



```
!\[示意图]\(../assets/images/示意图.png)
```

控制大小和对齐：



```
!\[图]\(../assets/images/a.png){ width="400" align=center }
```

**其他文件（PDF、数据、代码文件）：**



* 放进 docs 对应目录后，网站会原样保留，可在文档里链接下载：



```
\[查看论文原文]\(论文原文.pdf)

\[下载数据]\(附件数据.xlsx)
```



* PDF 点击可在浏览器直接打开；代码文件会显示为下载链接。

!!! warning "大文件不要进 docs"

单个文件几十 MB 以上、或整个合集上 GB（如 A053、大 zip），**不要放进 docs 和 Git**，只做一个索引页说明它在本地哪里。否则仓库会变得很臃肿、推送困难。

## 9. 怎么给文档打标签

在文档**最顶部**加一段（叫 front matter）：



```
\---

tags:

&#x20; \- 优化模型

&#x20; \- 线性规划

&#x20; \- 已吃透

\---
```

保存后，这个文档会自动出现在 [标签索引](tags.md) 对应标签下。

建议标签保持统一（参考 tags.md 里的推荐清单），不要一个意思造好几个标签（如同时有 "线性规划""LP""线性规划模型"）。

## 10. 本地预览与构建

**边写边看（推荐）：**



```
python -m mkdocs serve
```



* 改文件、保存，网页自动刷新

* 可以指定端口：`python -m mkdocs serve -a 127.0.0.1:8001`

**只生成网站成品（不启动服务器）：**



```
python -m mkdocs build
```



* 成品输出到 `site/` 文件夹，是纯静态网页

* `--clean` 表示先清空旧产物：`python -m mkdocs build --clean`

* `site/` 已在 .gitignore 里，不会被提交

## 11. Git 提交与推送

第一次使用，先初始化仓库并关联远程（远程仓库需先在 GitHub 建好，建议建**私有仓库** `YanYu-MathModeling`）：



```
Set-Location "D:\YanYuas\MathematicalModeling\YanYu-MathModeling"

git init

git branch -M main

git remote add origin https://github.com/你的用户名/YanYu-MathModeling.git
```

日常提交（写完一批内容后）：



```
git add .

git commit -m "说明这次改了什么，如：补充线性规划对偶理论笔记"

git push -u origin main
```

之后再推送，只需：



```
git add .

git commit -m "更新说明"

git push
```

**提交信息建议写清楚**，以后回看历史一眼知道每次做了什么。多人协作时各自开分支，合并前先拉取，具体分支规范可参考 HelloMathModeling 的《UGit 协作指南》。

## 12. 私有部署（Cloudflare Pages，含加密码）

目标：网站上线，但**只有授权的人能打开**。用 Cloudflare Pages（可以连私有仓库构建）+ Cloudflare Access（加访问验证）。免费额度个人完全够用。

### 第一步：把代码放到 GitHub 私有仓库

按第 11 节，把项目推送到 GitHub 的**私有仓库**。

### 第二步：Cloudflare Pages 连接仓库



1. 注册 / 登录 [Cloudflare](https://dash.cloudflare.com)

2. 左侧选 **Workers & Pages** → **Create** → **Pages** → **Connect to Git**

3. 授权 Cloudflare 访问 GitHub，选择 `YanYu-MathModeling` 私有仓库

4. 构建设置这样填：

* **Framework preset（框架预设）**：None（无）

* **Build command（构建命令）**：

  `python -m pip install -r requirements.txt && python -m mkdocs build`

* **Build output directory（输出目录）**：`site`

1. 点 **Save and Deploy**，等一两分钟，得到一个网址，形如 `https://yanyu-mathmodeling.pages.dev`

### 第三步：给网站加访问验证（关键，实现 "私有"）



1. Cloudflare 左侧选 **Zero Trust**（首次进入会让你选免费套餐、起一个团队名）

2. 进入 **Access** → **Applications** → **Add an application** → 选 **Self-hosted**

3. 配置：

* **Application name**：随便填，如 "我的数模库"

* **Subdomain / 域名**：选你刚才的 pages 域名（`yanyu-mathmodeling.pages.dev`）

1. 下一步 **Add a policy（添加策略）**：

* **Action**：Allow

* 配置谁能访问：规则里 **Emails** 填你自己的邮箱（团队成员就填多个邮箱）

1. 保存。

之后任何人打开网址，都会先跳到 Cloudflare 登录页：输入授权邮箱，邮箱会收到一个一次性验证码（Email OTP），填对才能看。这样网站虽然在线，却是私有的。

> 备选平台：Vercel 流程类似（连仓库、构建命令、输出目录），但 Vercel 的 "密码保护" 在付费版才完整；Cloudflare Access 免费版即可加访问控制，所以首选 Cloudflare。

### 上线后更新内容

以后本地写完、`git push` 之后，Cloudflare 会**自动重新构建并更新网站**，不用手动操作。

## 13. 内容怎么迁移进来（重要）

为避免 "一份资料两处改、越改越乱"，约定清楚数据流向：

### 单一数据源原则



* \*\*`docs/` 是网站内容的唯一权威来源。\*\* 以后写笔记、改内容，都在 docs 里改。

* 原来的数模文件夹作为**原始底档保留**（不删任何东西），但迁移之后，主要在 docs 维护。

### 不同类型资料怎么搬



| 类型                       | 怎么处理                            |
| ------------------------ | ------------------------------- |
| Markdown 笔记（.md）         | 复制进 docs 对应分区，之后只在 docs 改       |
| 代码（.py/.m）               | 放进 docs 对应分区目录（可下载），或在笔记里用代码块呈现 |
| Jupyter Notebook（.ipynb） | 直接放进 docs，网站自动渲染（含运行结果）         |
| 图片                       | 放 `assets/images/` 或分区 images   |
| PDF / Word / 数据文件        | 放进 docs 对应目录，在 md 里链接           |
| 大压缩包 / A053 合集           | 不进 docs，只做索引页                   |

### 建议的迁移顺序（先熟后生）



1. **00 优化模型**：资料最成熟，先完整搬进来，作为样板

2. **01 竞赛作品**：国赛范本 + 团队进步史

3. **07 协同模板**、**02 培训课件**

4. **04 优秀论文**：边精读边搬（不是一次性全塞）

5. **03 赛题库**：量大，按需搬，或做索引

6. 其余专题（02-11 算法）：随着学习逐步填充

!!! tip "迁移一份，加工一份"

不要机械复制。每搬一份，顺手加上自己的话：什么时候用、怎么用、踩过什么坑。这才是 "你的" 知识库。

## 14. 常见问题排查

**Q：提示&#x20;**`mkdocs 不是内部或外部命令`**&#x20;/&#x20;**`No module named mkdocs`

环境没装好，运行：



```
python -m pip install -r requirements.txt
```

注意统一用 `python -m pip`（避免 pip 指向别的 Python 版本）。

**Q：中文搜索搜不到 / 结果不准**

确认装了 jieba（`python -m pip install jieba`）。它在**构建时**给中文分词；改完内容重新 `serve` 或 `build` 即可。

**Q：公式不显示，显示成原始符号**

检查：①公式符号是否写对；②mkdocs.yml 里 mathjax.js 和 CDN 是否还在；③网络是否能访问 jsdelivr（离线时公式不渲染，正文不受影响）。

**Q：构建时一堆 WARNING 说链接目标不存在**

这是因为对应页面还没迁移 / 创建。把链接指向的文件补上即可；暂时不用的链接先删掉或标注 "待补充"。WARNING 不影响网站生成。

**Q：页面没有显示 "最后更新时间"，或提示没有 git 记录**

该插件依赖 Git。先按第 11 节 `git init` 并做一次提交，之后时间就正常了。

**Q：改了文件网页没变化**

确认文件保存在 `docs/` 里；检查 `mkdocs serve` 是否还在运行；浏览器强制刷新（Ctrl+F5）。

**Q：想换一种风格**

按 `docs/stylesheets/cream-candy.css` 顶部的接口说明：复制改色、在 mkdocs.yml 的 extra\_css 里替换文件即可，内容不用动。

**Q：想加参考文献引用**

装了 mkdocs-bibtex。准备好 `refs.bib` 后，在 mkdocs.yml 的 plugins 里加入 bibtex 配置（指定 bibtex\_file），再在文中用 `\cite{key}`。骨架阶段未启用是为了避免缺少 bib 文件时报错。
