## 关键的公式渲染问题与结论

题库 md 的块级公式 `$$...$$` 大量写在**列表项内部**（`- **解答**：` 的缩进续行），
`pymdownx.arithmatex` 的块级识别会失败，退化为行内并残留 `$$` 字面量。

处理与结论：
- 48 处缩进单行 `$$...$$` 已改写为顶格三行块级（`tools/fix_block_formula.py`），
  其中 F1/F2 的 44 处生效。
- 剩余 F1（62 处）、F2（2 处）因仍在列表上下文内，arithmatex 无法转换，
  **交由 MathJax 原生 `$$` 定界符兜底**。
- 依据：查 MathJax 3 源码确认 `OPTIONS.displayMath = [["$$","$$"],["\\[","\\]"]]`，
  `$$` 本就是默认块级定界符，且匹配在文本节点级进行，
  不要求独占一行；实测生成的 HTML 为 `<p>$$\n...\n$$</p>`，配对同父元素，可正常渲染。
- `mathjax.js` 已配置双轨：`inlineMath` 增加 `["$","$"]`，`displayMath` 增加 `["$$","$$"]`，
  两者兼容 arithmatex 输出与原生写法。

### 关键发现：这些 HTML 里根本没有 LaTeX

正文内反斜杠总数为 **0**，无 `$`、无 `\alpha`/`\begin`、无 katex 元素。
所有数学内容都是 **Unicode 数学字符**（α₁、∈、∑、‖·‖、ᵀ、⁻¹）。
→ 因此转换无需处理公式定界符，直接保留文本即可。这点与题库 md 完全不同。

### 踩过的两个坑（重要）

1. **HTMLParser 的 skip 计数器 bug**：最初用 `skip_depth += 1` / `-= 1`，
   但被跳过子树**内部每个结束标签都会误减计数**，导致 `<nav>` 内第一个 `</div>`
   就提前结束跳过，TOC 内容混进正文开头。
   正解：用 `skip_frames` 记录被跳过子树的根节点在 stack 中的索引，
   只有结束标签回到该索引时才出栈。
   → 通用教训：树形跳过必须用「记录深度」而非「计数器」。

2. **Markdown 把算式 `[xxx](yyy)` 当链接**：如 `[(0.5-0.5+1)/1.5](0.5,-0.5,1)`。
   新增 `tools/fix_bracket_paren.py` 转义为 `\[xxx](yyy)`。
   注意：判断「是否真链接」不能在正则里用负向预查排除
   （本地路径含中文，字符类匹配不上会误伤正常链接），
   必须在替换函数里用 `LINK_TARGET` 判断。
   另：脚本对已处理文本再跑一次会产生双反斜杠 `\\[`，需避免重复执行。
